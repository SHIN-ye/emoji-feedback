# 部署与用户手册

## 本地运行与账户
按 README 建立虚拟环境并安装锁定依赖。运行 `python -m scripts.seed --demo` 显式创建随机密码的演示账户；普通服务启动不生成默认管理员。注册学生可直接使用；教师和管理员注册分别需要环境变量 TEACHER_INVITE / ADMIN_INVITE 中的邀请码。若未配置则关闭相应角色的自助注册。

PowerShell 中设置环境后启动服务，例如 `$env:TEACHER_INVITE='部署者生成的长随机值'`。本地应用不会自动读取 .env；Compose 会读取同目录 .env。不要把生产邀请码或 AI 令牌发到学生端。

## 学生操作
1. 注册学生账户并登录。
2. 管理员创建课程课堂并把你的账户加入课堂名单。
3. 在“我的课堂”选择课堂，课堂时间与安排生效后点击表情。
4. 在“情绪记录”按课程、班级、时间和来源查询本人记录。
5. 在“账户设置”修改密码；所有旧会话失效，重新登录。

## 教师操作
以教师邀请码注册，或使用本地演示 teacher。管理员必须把课程授课人指定为你的账户。课堂看板每五秒刷新当前课堂汇总，显示最近反馈、分布和按分钟记录数量。多维统计支持课程、班级、时间段和来源。只能查看自己授课的课程，不能导出管理员 CSV。

## 管理员操作
课堂管理中先创建课程，指定有效教师；再创建课堂，填写班级、教室和起止时间；最后勾选学生并保存安排，可设未来生效时间。名单保存为增量添加/更新时间，不清空原名单。用户管理支持停用/启用，停用即撤销会话。情绪记录页面先查询，再导出同条件 CSV。CSV 带 UTF-8 BOM，并对公式开头的字段加单引号。

## PostgreSQL 容器部署
安装 Docker Desktop 并启用 Compose。复制 `.env.example` 为 `.env`，填写四个独立随机值。数据库密码使用 URL 安全字符，防止连接 URL 解析歧义。
```sh
docker compose up --build -d
docker compose logs app
```
浏览器访问本机8000端口。先使用管理员邀请码从注册页创建管理员，再使用教师邀请码创建教师。学生自行注册。数据库通过命名卷持久化；不要使用 `docker compose down -v`，它会删除该卷。
停止：`docker compose down`。结构初始化由应用启动自动完成，SQL 参考 `schema-postgresql.sql`，不要在已初始化数据库重复运行建表脚本。对外访问需要自行配置域名、HTTPS 和反向代理，当前端口仅绑定本机。

## AI 服务
建议另建 Python 3.12 虚拟环境，安装 ai/requirements.txt。DeepFace 首次运行可能下载模型权重，需网络和足够磁盘；主系统不依赖这些大包。
后端与 AI 进程分别设置相同 AI_SERVICE_TOKEN。显式启动命令：
```powershell
python -m ai.worker --source 0 --session 1 --interval 3 --threshold 0.6
```
source 为摄像头编号或本地视频路径；session 必须是有效课堂。文件每隔指定视频秒数采样，摄像头按实际时间采样；记录时间是分析采样发生的 UTC 时间。使用录像演示仍需当前有效课堂。没有有效人脸时不提交，低置信度过滤，网络错误最多尝试三次；三次失败记录日志并丢弃该事件，当前不提供持久化离线队列。摄像头断开最多重连三次。按 Ctrl+C 退出。所有帧仅存在内存，不写图片和视频文件。

## 故障排查
401：会话过期、已改密、账户停用或令牌错误。403：角色/课堂越权或安排未生效。400：课堂过期、起止时间不正确等业务问题。409：用户名重复、AI 事件冲突或并发数据冲突。422：表单字段、密码或时间格式错误。
页面没课堂：检查是否安排当前学生或课程教师是否正确。看板没数据：确认选中课堂、筛选条件和时间。AI 结果少：检查阈值、光线、遮挡与课堂时间；降低阈值会增加误判，不能把数量当作准确性证据。

## 运维边界
日志不应包含密码或令牌。数据库备份采用 PostgreSQL pg_dump；SQLite 演示环境应停服务后复制 emoji.db。当前尚无数据库版本迁移工具、登录限流、监控告警和大规模负载验证；对公网正式使用前需补充这些措施。

## AI 摄像头启动与独立验收（2026-11-12）

AI 使用独立 Python 3.12 环境 `.venv-ai`。安装：
```powershell
.\.venv-ai\Scripts\python.exe -m pip install -r ai/requirements.txt
```
后端启动前和 AI 启动前，设置相同的 `AI_SERVICE_TOKEN`。在管理端创建当前有效课堂，记下课堂 ID：
```powershell
.\start-ai.ps1 -Session 课堂ID -Source 0 -Duration 20
```
省略 Duration 表示持续运行，Ctrl+C 停止。模型先加载，然后打开摄像头；首次加载可能下载权重。每三秒采样一次，默认置信度阈值 0.6。终端输出情绪、置信度、入库结果和最终计数。教师选择对应课堂后，五秒轮询可读到 AI 数据。无脸或全部低于阈值时不会产生记录。

开发验收可运行以下命令（需在 AI 环境额外安装根目录 requirements.txt）：
```powershell
.\.venv-ai\Scripts\python.exe -m scripts.verify_ai_camera --duration 20
```
该命令实际打开摄像头，创建临时本地 HTTP 服务、独立课堂和 SQLite 数据库，执行真实 AI worker，随后以教师身份读取历史和看板。输出位于 artifacts/ai-camera-时间戳，包含 worker.log、result.json、verification.db，不含图像或视频。只有 worker 正常退出、真实产生 AI 记录且教师看板数量一致才标记通过。该测试数据库不会混入日常演示库。

自动测试 test_ai_pipeline.py 使用模拟模型输出验证七类情绪到真实数据库及看板的数据流程，不代表真实模型准确率或摄像头测试。

复现本机已经安装并检查过的完整 AI 验收环境，可在 Python 3.12 虚拟环境执行 `pip install -r ai/requirements-lock.txt`。锁定文件包含后端验收依赖。模型默认缓存于 `artifacts/ai-model-cache`，通过 `DEEPFACE_HOME` 可覆盖。若摄像头打不开，请先检查 Windows 相机能否显示画面、物理开关及摄像头占用；本机首次实测目前停在此步骤，不能将其记为通过。

### Windows 独立采集方式

如果 Windows 相机能正常使用，但 AI 环境打开设备返回拒绝访问，可用独立 Python 启动摄像头采集，再通过本机二进制管道把帧交给 AI 环境。该方式已用本机 Python 3.15.2 采集、Python 3.12 推理实测通过，帧不写入磁盘。

在项目目录执行以下命令。首次安装采集依赖，后续可直接执行最后一行。将 `$cameraPython` 指向本机能够打开设备的独立 Python。

```powershell
$cameraPython = Join-Path $env:LOCALAPPDATA 'Programs/PythonProject3152/tools/python.exe'
& $cameraPython -m pip install --target artifacts/.camera-runtime pygrabber==0.2
& $cameraPython -c "import runpy,sys; sys.path.insert(0,'artifacts/.camera-runtime'); runpy.run_module('ai.camera_pipe',run_name='__main__')" --verify-with .\.venv-ai\Scripts\python.exe --duration 20
```

验收命令创建隔离数据库，结束后打印 `passed` 与 `AI_records`。关闭其他相机应用并在采样期间面向镜头。日常连接现有课堂时，可在 PowerShell 7.4 及以上将同一采集命令（省略 `--verify-with`）的二进制标准输出传给 `python -m ai.worker --capture-stdin --session 课堂ID`，按原部署方式配置 AI 令牌。
