# 表情符号课堂情绪检查器系统项目计划书

版本 2.0，更新日期 2026 年 11 月 14 日。依据《表情符号课堂情绪检查器系统》实验指导书，记录项目范围、技术选型、实施阶段和最终交付安排。

## 1 项目目标与范围
面向学生、教师和管理员构建课堂情绪反馈系统。以学生主动反馈为核心，摄像头分析作为辅助数据源。完成需求、设计、编码、测试、部署和答辩材料全过程。浏览器客户端满足指导书允许的客户端选型；AI 独立 Python 进程，通过服务认证接口提交结果。

必做：学生注册登录改密、手动提交和个人历史；教师所授课堂历史及统计；管理员注册登录、用户管理、课程和课堂管理、定时人员安排、数据查询和 CSV 导出；实时情绪看板、课程/班级/时间多维统计；至少五类 AI 情绪、采样配置、阈值过滤、匿名入库、重试日志；后端权限校验、哈希密码、API 文档和完整测试。

不纳入初版：人脸身份识别、自训练模型、心理诊断、消息队列、MCP 工具封装。Docker Compose 提供部署配置；真实容器和摄像头验收必须与自动测试分开记录。

## 2 方案比较与选型
方案 A：Android + Spring Boot，移动端体验好但四人小组学习和联调成本高。方案 B：Vue + FastAPI，组件生态丰富但新增前端构建链。方案 C（本次采用）：模块化原生 JavaScript 浏览器客户端 + FastAPI + SQLAlchemy + PostgreSQL + 独立 Python AI，减少环境成本，保留清晰的 View / Controller / Model 分工。若后期页面规模扩大，可替换为 Vue 而保持 API 不变。

本地 SQLite 仅用于开发和测试；正式部署 PostgreSQL。身份认证采用服务端 Session（高熵 Bearer 令牌、数据库仅存令牌摘要、过期与注销机制），满足指导书 JWT 或 Session 二选一。所有时间持久化使用 UTC，页面按用户时区展示。

## 3 角色与用例
学生：注册为学生→登录→查看已安排课堂→在课堂有效时间内提交表情→查询本人历史→改密/注销。
教师：使用教师邀请码注册→登录→查看本人课程与课堂→查看学生反馈、匿名 AI 汇总和趋势。无权访问其他教师课堂。
管理员：使用管理员邀请码注册（由部署者配置）→创建课程和课堂→安排学生及生效时间→管理用户状态→查询和导出全部数据。
AI：独立服务令牌→读取本地指定视频/摄像头→按采样间隔分析→过滤低置信度→携带唯一事件 ID 提交→失败有限重试。重试不会重复入库。

## 4 架构与数据设计
浏览器 View（HTML/CSS）→Controller（事件/路由/刷新）→Model（API/状态）；后端 Controller（HTTP 与输入输出）→Service（授权和规则）→Repository（SQLAlchemy 查询）→数据库。AI 通过 REST 与后端解耦，不直连数据库。

核心表：User(id,username,password_hash,role,email,status,created_at)；Course(id,name,teacher_id)；ClassSession(id,course_id,class_name,room,start_time,end_time)；ScheduleUser(id,session_id,user_id,scheduled_at)；EmojiRecord(id,user_id可空,session_id,emoji,timestamp,source,confidence,device_id,event_id唯一)；AuthSession(token_hash,user_id,expires_at)；AuditLog(id,user_id,action,timestamp)。
外键完整性、课堂起止时间、角色/情绪/来源枚举、同课堂同学生安排唯一、AI 事件唯一均约束。情绪：happy 开心、neutral 平静、sad 低落、angry 生气、surprise 惊讶、fear 紧张、disgust 反感。AI 分类不代表真实心理状态。

## 5 接口契约
所有业务成功返回 {code:0,data:...}，错误返回 {code:HTTP状态,message:...}。版本 1 在 /api 下，破坏性变更新增 /api/v2。
认证：POST /api/auth/register、/login、/logout，PUT /api/auth/password。
用户：GET /api/users/me、GET /api/admin/users、PATCH /api/admin/users/{id}。
课程课堂：GET /api/courses、/api/sessions；POST /api/admin/courses、/api/admin/sessions、/api/admin/sessions/{id}/schedule；GET 同路径查看名单。
情绪：POST /api/emoji；GET /api/emoji/history、/api/emoji/statistics。
看板：GET /api/admin/dashboard/realtime?sessionId=，页面每 5 秒轮询（可见页面才刷新，显示更新时间和错误状态）。
统计：GET /api/admin/statistics?course=&class=&from=&to=&source=；教师接口仍强制限定本人课程。
AI：POST /api/ai/emoji-results，使用 X-AI-Token 独立认证；导出 GET /api/admin/emoji/export?format=csv。交互式文档 /docs，机器可读 /openapi.json。

## 6 安全与隐私
密码至少 10 位，包含字母和数字，随机盐 PBKDF2-HMAC-SHA256。用户不能通过普通注册任意提权；教师/管理员邀请码由环境配置。改密撤销全部旧会话，禁用账户立即阻止访问。所有业务端点在后端校验角色和数据所属关系。CSV 对公式前缀 = + - @ 制表符及换行进行防护。SQL 使用参数绑定。AI 默认匿名，仅持久化统计所需字段；不保存图像和视频。不自动打开摄像头。演示账号仅由显式初始化命令生成。

## 8 实施步骤
1. 固化计划、需求与架构，建立本地仓库和独立虚拟环境。
2. 先写接口验收测试，再实现认证、权限、课程课堂、安排和手动反馈。
3. 实现统计、实时看板接口、导出、AI 接口与防重复机制。
4. 构建完整浏览器界面，连接真实接口，检查桌面与窄屏。
5. 实现独立 AI 采样与提交程序；使用模拟输出测试协议，真实模型/摄像头另行验收。
6. 完成部署、数据库脚本、用户手册、测试报告和答辩材料。
7. 运行完整测试，独立代码审查并修复问题，记录已验证与待人工确认事项。

## 9 验收与质量门槛
核心链路：注册→管理员安排→学生提交→教师查到→管理员导出；其他学生与其他教师不能读到记录。无效/过期令牌拒绝，弱密码拒绝，改密旧令牌失效。未安排和不在课堂时间不能提交。统计按筛选准确，手动/AI 可区分，匿名 AI 不计作学生参与人数。无数据时显示空状态。
AI 低置信度不入库、错误令牌拒绝、事件重试不重复；无脸不产生伪造记录。测试报告明确协议测试不等于真实识别精度测试。容器部署未实际运行不能标记通过。

## 10 风险与应对
模型依赖/权重下载大：独立依赖、延迟导入；先验证数据流程。课堂多人遮挡/光线差：记录局限，不宣称准确率。环境无 Docker：提供配置并明确待验证。接口联调冲突：统一响应和字段，自动测试守护契约。数据泄露：后端作用域过滤。实时轮询负载：仅当前视图每五秒查询，后续可升级 WebSocket。
