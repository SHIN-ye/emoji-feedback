# 实验报告草稿与答辩准备

## 实验目标
实现学生课堂情绪记录、教师观察和管理员管理系统，练习需求建模、修改版 MVC、REST API、关系数据库、权限、AI 集成与测试。

## 实施方法与成果
使用浏览器客户端覆盖三类角色，后端按 Controller / Service / Repository 分层。用户、课程、课堂、人员安排、情绪记录、登录会话和审计日志构成核心数据模型。学生主动选择表情，AI 通过独立服务认证接口提交匿名分类。数据按课堂聚合，支持课程、班级、时间和来源筛选，并提供 CSV。
自动验证及局限以测试报告为准；不将尚未运行的容器、摄像头和模型识别写作已完成实验。

## AI 局限性分析
面部表情与内心情绪没有一一对应关系。光线、角度、遮挡、多人画面、不同文化和个体差异都会影响结果。分类模型的置信度并非经过本课堂数据校准的正确概率。连续帧可能对同一人重复采样，AI 记录条数不能代表参与人数。模型中性表情不能直接解释为理解课程，悲伤表情也不能当作心理诊断。
本系统只进行辅助课堂统计；主动反馈与 AI 分开标注；默认匿名且不保存原始图像。现场应使用知情、适当授权的测试参与者或允许使用的样例视频。准确率、延迟等指标需通过标注样本实测，本报告不编造指标。

## 可复现实验记录模板
日期、机器配置、Python/模型版本、摄像头/视频来源、参与人数、课堂ID、采样频率、置信度阈值、成功入库数、低置信度过滤数、异常日志、人工标注与误判示例、结论。未填写部分保持“待测”。

## 常见答辩问题
为什么采用修改版MVC？前端界面/控制/数据访问分开；后端把业务从控制器移至Service，把数据库操作交给Repository；独立AI通过接口接入。
如何避免越权？每次请求服务端验证会话和角色，查询按本人或所授课程限定，不能仅靠隐藏按钮。
如何防止AI重试重复？每条事件使用唯一event_id；同内容重复返回原ID，不同内容冲突；并发唯一约束阻止重复写入。
为什么默认匿名？课堂统计不需要人脸身份识别，减少个人数据持久化。
实时如何实现？当前页面可见时五秒轮询；后续可改WebSocket，当前无需承担连接管理成本。
